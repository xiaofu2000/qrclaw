# QRClaw 官网计划

日期：2026-10-20

状态：用户否定首版后，已基于免费参考完成连续三维叙事重设计。独立审阅的七项修正已复判 resolved；下方保留首版规划作为历史。当前实现以 DESIGN.md、docs/REFERENCE-RESEARCH.md、docs/REVIEW.md 与 docs/VALIDATION-REDESIGN.md 为准。

## 1. 产品定位与目标

QRClaw 是本地运行的 AI Agent，提供中文 Web 工作台、CLI 和 OpenAI 兼容 API。用户通过对话交代任务，Agent 调用工具完成工作，支持按需规划、子任务协作，以及可查看、编辑和追溯来源的跨会话 Wiki 记忆。

官网的核心表达：

> 把任务交给它，把经验留下来。
>
> QRClaw，你的本地 AI 工作伙伴。

目标读者优先考虑独立开发者、AI 工具使用者，以及愿意配置模型 API 的个人用户。让首次访问者理解产品能做什么、看到实际工作过程，并能找到源码与启动方法。

首版做中文产品介绍单页，包含快速开始和常见问题。主要行动是“开始使用”，次要行动是“查看 GitHub”。安装入口以源码运行说明为基础，不假设存在已经发布的安装包。

## 2. 事实依据

本次核对了本地 README.md、PRODUCT.md、DESIGN.md、web/README.md、pyproject.toml、工具与运行时入口，以及 GitHub 公开仓库。

| 已有能力 | 官网如何表达 |
| --- | --- |
| 对话、文件与 Shell 等工具执行 | 用一个真实样例展示任务输入、执行过程和结果 |
| 默认直接执行；可开启 Plan | 简单任务直接处理，复杂工作可按计划推进 |
| 子 Agent 及可展开的执行记录 | 展示任务拆分、子任务进度与结果查看 |
| Wiki 长期记忆与管理页面 | 展示跨会话复用、来源追溯、编辑和删除 |
| Skills 与 MCP 工具接入 | 说明可以按任务扩展能力；实际可用范围取决于配置 |
| Web、CLI、OpenAI 兼容 API | 给不同使用方式清晰的入口 |

上述是现有文档和实现入口支持的能力说明，并非本轮已经运行通过的验收结果。官网演示需在实施阶段另外录制和验证。

内容边界：

- 本地运行不等于所有推理离线；使用远程模型服务时，相关请求会发送给配置的服务商。
- 记忆需要满足提取条件或主动写入，避免宣称每句话都会即时、准确地被永久记住。
- 默认 Agent 未启用 Docker 沙箱，不使用“默认完全隔离”之类表述。
- 官网显示真实界面，示例数据和步骤回放标为演示；不提供连接用户本机 Agent 的公共聊天入口。
- 不编造用户数量、合作企业、推荐语、性能提升比例或 GitHub 热度。

## 3. 视觉方向

设计判断：面向开发者和个人 AI 用户的产品官网，以明亮、清晰、有适度动态反馈的工作伙伴形象为主，采用非对称排版与真实产品画面。

延续现有白色工作面、蓝灰辅助色和钴蓝重点色（#315cda），官网增加更大的标题、更充足的留白和更有节奏的页面构图。首屏采用左侧文案、右侧真实产品演示；后续用横向流程、图文交错、大幅界面细节和紧凑文档区形成变化。

英文品牌文字和大标题候选使用 Fontshare 的 Satoshi；中文优先系统无衬线字体。字体文件是否引入，以实际中文混排效果、授权和体积为准。

动态效果服务于“交代任务 → 看见执行 → 留下记忆”的叙事：

- 首屏演示允许主动播放、暂停，默认静音。
- 中段随着阅读逐步解释任务、工具调用和记忆的关系，同时允许点击切换步骤。
- 页面保留自然滚动，手机采用纵向布局。
- 减少动态效果时提供静态画面，离开视口或后台时暂停不必要的动画。

QRClaw 字标作为官网主标识。现有黑色工作伙伴可出现在真实产品画面中，但其上游说明明确区分代码 MIT 许可与 Grok / x.ai 形象设计权利；不把该角色宣称为 QRClaw 原创品牌资产。

| [Spline](https://spline.design/) | 有限候选 | 仅在能帮助解释任务与记忆关系时加入一处轻量 3D 场景；先用静态稿确认价值 |

资源是否付费、能否下载或导出，在实际选材时核对。首版以可用的免费资源和自有素材推进，计划不依赖购买订阅。

## 5. 页面结构

| 顺序 | 内容 | 具体呈现 |
| --- | --- | --- |
| 1 | 首屏：QRClaw 是什么 | 主标题、两句定位、真实界面演示、“开始使用”“查看 GitHub” |
| 2 | 一项任务如何完成 | 用安全的本地样例材料展示输入、计划或直接执行、工具结果、最终交付 |
| 3 | 经验如何留下来 | 放大记忆管理界面，解释来源、修改和下次对话复用 |
| 4 | 工作过程看得见 | 展示工具日志、子任务卡片和状态反馈，用界面细节证明功能 |
| 5 | 按自己的方式扩展 | 展示 Skills、MCP，以及 Web / CLI / API 三种入口 |
| 6 | 快速开始 | 环境要求、获取源码、安装依赖、配置模型、启动工作台；命令可复制 |
| 7 | 常见问题与页脚 | 本地运行、模型 API、费用构成、记忆管理、源码和许可链接 |

建议演示题材：整理一组专门准备的项目笔记并输出摘要，再保存用户指定的输出偏好，展示后续任务如何复用。实施时先实际运行，再根据可稳定复现的结果决定最终录屏脚本。不能稳定展示的能力不放进主宣传演示。

## 6. 目录与技术安排

官网统一放在仓库根目录 `website/` 下，独立运行和部署。以下为原计划目录骨架；实际实现另外包含 src/、tests/、tools/ 与设计文件：

```text
website/
  PLAN.md                  官网计划
  README.md                本地预览、维护和发布说明
  docs/                    文案依据、视觉规范、素材来源与验收记录
  site/                    可直接托管的静态站点
    index.html
    assets/                截图、录屏、字体、图标
    styles/                页面样式与设计变量
    scripts/               演示、复制按钮、导航等轻量交互
```

首版优先静态 HTML / CSS / JavaScript，不引入服务端、账号系统或数据库。展示内容与交互状态分离；如交互复杂度确实需要 React，则在官网目录独立配置构建，将状态逻辑放入 ViewModel，组件负责渲染。

官网的构建和发布不调用现有 `web/` 的发布脚本，避免把营销页面写入 `qrclaw/server/static`。原客户端及后端不作为官网的运行依赖。

部署阶段可使用 Sites；遵循其站点身份、源码同步和发布流程。新站默认私有，正式公开访问及自定义域名在发布阶段明确。实施阶段已创建独立私有站点；最终状态见 docs/VALIDATION.md。

## 7. 实施顺序与阶段交付

1. **内容和素材**：核对页面中的每项能力、正确的源码链接和安装路径，准备安全样例与真实截图，产出文案和演示脚本。
2. **视觉定稿**：完成可在浏览器查看的首屏与一个核心内容区，确定字体、配色、构图和动态节奏，再展开整页。
3. **完整页面**：补齐七个内容区、手机布局、导航、命令复制、FAQ 和演示控件。
4. **验证与修复**：检查桌面与手机、键盘操作、减少动态效果、链接、资源加载、控制台错误及基础性能；修复后记录结果。
5. **交付与发布**：提供源码、预览、素材来源、维护说明和验证记录；按发布范围完成托管与域名配置。

阶段交付用于让设计尽早可见，不要求每做完一步都重新申请确认。遇到品牌授权、付费资源或公开范围等确实影响交付且无法按现有授权解决的事项，再提交具体选项。

## 8. 验收标准

以下均为未来验收项目，目前尚未执行：

- 首屏可读出产品名称、用途和开始使用入口。
- 每项主要功能能对应到真实产品画面或明确标记的演示。
- 360px、390px、768px、1440px 宽度下无横向溢出、遮挡和不可访问的按钮。
- 导航、复制命令、演示播放/暂停、FAQ 和外链都可实际使用。
- 快速开始步骤从干净测试目录核对，涵盖模型配置，不误报为无需配置即可使用。
- 键盘可操作；焦点可见；正文与按钮对比度达标；减少动态效果可用。
- 无页面控制台异常、关键资源 404 或主操作死链。
- 大幅图片、录屏和可选 3D 延迟加载；移动端不因装饰动效阻塞主要内容。
- 性能目标参考移动端 LCP ≤ 2.5 秒、CLS ≤ 0.1，交互响应目标 INP ≤ 200ms；记录测量条件，实验室检查不冒充真实用户数据。
- 页面 title、description、社交分享图与 favicon 完整；公开域名确定后补充 canonical 和索引配置。
- 验收记录明确区分已验证、未验证及已知限制。
