# Agent 记忆与上下文管理方案

## 整体结构

| 层 | 载体 | 作用 |
|---|---|---|
| 短期 | 每个会话一个 JSON 文件（消息 + 过程事件 + 用量） | 当前任务的工作上下文 |
| 长期 | Wiki 页面库：一个主题一页 Markdown + 索引 | 跨会话复用的知识 |

两层之间的衔接：**上下文压缩前，先把即将丢弃的原文送进记忆提取队列**，压缩不会造成知识丢失。

---

## 一、上下文管理

### 1. 用量估算
- 总用量 = 消息 token + 系统提示词与工具定义 token。
- 后者只在系统提示词重建时算一次并存下，平时不重复计算。
- 用当前模型对应的分词器计数，不用通用估算。

### 2. 分角色视图
同一份会话历史，按调用方裁剪：

| 角色 | 输入 |
|---|---|
| 执行者 | 系统提示词 + 完整历史 |
| 路由 | 用户消息 + 无工具调用的助手正文 + 执行报告 |
| 重规划 | 目标 + 已完成步骤结果 + 剩余步骤（不带聊天历史） |

### 3. 压缩
每次调模型前检查，用量超过窗口 **90%** 时触发：
- 从最新消息往回保留约 **12%** 窗口的原文，按 token 算，不按条数；
- 保留区开头如果是孤立的工具结果就挪出去，保证工具调用和结果成对；
- 其余部分由模型写成四段式摘要：用户信息 / 已完成任务 / 关键结论 / 待处理事项；
- 旧摘要一并参与下一次压缩（递归摘要）；
- 压缩后总量控制在 **20%–25%**，超了就收紧保留区；
- 写回前重新读盘比对，期间会话被改过就放弃，避免覆盖并发写入；
- 开始 / 完成 / 失败各记一条事件，前端据此展示进度。

### 4. 子任务隔离
- 复杂任务按依赖关系分层，同层并行，每个步骤交给一个子 Agent；
- 子 Agent 使用独立会话文件，看不到主会话历史；
- 输入只有：总目标、项目根目录、前置步骤结果（状态 / 输出 / 新建和修改的文件）、当前任务；
- 输出要求是纯文本结果摘要，回到主流程后存为步骤结果。

### 5. 系统提示词缓存
缓存后只在三种情况失效：注入了召回的记忆、计划结束、发生压缩。

## 二、长期记忆

### 1. 存储
```
memory/
├── pages/*.md          页面，frontmatter 含 description / tags / related / revision / status
├── index.json          索引（唯一可信来源）
├── index.md            由 index.json 生成
├── log.md              操作日志
├── .wiki-state.json    来源追溯、页面版本、已删除页面
└── .extractions/*.json 每个会话的待提取进度
```

### 2. 写入

**自动提取**（后台、批量）：
- 只收用户和助手正文，过滤工具消息、执行报告和摘要；
- 每个会话只维护一个合并批次，进度落盘；
- 每条消息按「角色 + 正文」算指纹，用户编辑过的消息会重新提取；
- 触发条件：
  - 满 **3 轮**且闲置 **120 秒**；
  - 或待处理内容 ≥ **5000 token**，不等闲置；
  - 或压缩前保存的原文，强制处理；
  - 两次之间冷却 **300 秒**；
- 模型输入「当前索引 + 新对话」，对每个主题输出 `create / append / skip`，并附上来源消息 ID。来源必须真实存在，且要有用户消息支撑，助手的推测不算；
- `append` 不直接追加，而是再调一次模型，把新旧内容合并成完整正文后替换：新事实覆盖旧事实，无法判断的冲突标为待确认。

**主动写入**：仅在用户明确要求“记住”“以后都这样”时，Agent 才调用工具立即写，不受轮次、闲置、冷却限制。已分析的会话正文从自动批次中移除；分析期间新增或编辑的正文保留，其他长期信息仍由后台自动整理。

### 3. 读取

| 级别 | 方式 | 时机 |
|---|---|---|
| 索引常驻 | 每页一行「名称：描述」注入系统提示词 | 每次 |
| 工具检索 | 搜索 / 列表 → 分页读正文；同一版本的同一段只返回一次 | 模型自行决定 |
| 自动召回 | 关键词粗筛 ≤20 个候选 → 模型精选 3 页 → 正文注入系统提示词 | 仅复杂任务（走规划路线时） |

### 4. 一致性
- **来源追溯**：页面记录来源消息。用户删改了原消息，相关页面进入修复队列，由后台在闲置时按剩余有效来源重建；修复期间页面对 Agent 不可见。
- **版本校验**：合并时带上旧页面快照，提交时发现页面已变就放弃。
- **删除保护**：主动删除的页面记入墓碑，旧的后台任务不能把它写回来。
- **幂等**：同一批次的结果重复提交只生效一次。
- **失败重试**：失败时原文留在磁盘，冷却后重试；服务重启后自动续接。
- **加锁**：模型生成内容时不持锁，只在提交时短暂持锁并校验。

## 三、请求流程

1. 请求开始：暂停记忆提取计时。
2. 路由：简单任务直接执行；复杂任务先召回记忆，再拆步骤交给子 Agent。
3. 每次调模型前：检查用量，必要时压缩，压缩前原文先入提取队列。
4. 按角色组装消息并调用，结果写回会话。
5. 请求结束：新正文入提取队列，等闲置后在后台写入长期记忆。

## 四、参数

| 参数 | 值 |
|---|---|
| 压缩触发 | 窗口 90% |
| 保留近期原文 | 窗口 12% |
| 摘要目标 | 窗口 10% |
| 压缩后总量 | 窗口 20%–25% |
| 提取最少轮次 | 3 |
| 闲置等待 | 120 s |
| 提取冷却 | 300 s |
| 长对话兜底 | 5000 token |
| 自动召回 | 粗筛 20 → 精选 3 |

窗口大小、压缩阈值、保留预算和提取相关参数都可以通过环境变量调整。
