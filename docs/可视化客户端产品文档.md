# QRClaw 可视化客户端产品文档

> 版本：0.2 精简讨论稿  
> 日期：2026-08-18  
> 首发：macOS 本地 Web

## 1. 产品结论

QRClaw 客户端定位为：

> 本地优先、执行过程透明、用户可以随时控制的多 Agent 工作台。

它不是普通聊天客户端。聊天只是任务入口，产品重点是让用户看见并控制：

- 主 Agent；
- 子 Agent；
- 任务计划；
- 当前步骤；
- 工具调用；
- 结构化思考摘要；
- 文件变更；
- 权限请求；
- Replanner 调整；
- 最终结果。

## 2. 已确认的产品决策

| 事项 | 决定 |
|---|---|
| 产品定位 | 多 Agent 工作台 |
| 首发形态 | 本地 Web |
| 首发系统 | macOS |
| OpenWebUI | 不保留，删除相关接入、脚本和文档 |
| React 原型 | 保留三栏布局思路，代码按 MVVM 重构 |
| UI 布局 | 方案 A：对话与任务时间线为主，右侧任务检查器 |
| UI 主题 | 白色浅色主题，不采用黑色深色主题 |
| 信息密度 | 中等偏高，保持专业开发者工具风格 |
| 工具权限 | 只支持“允许一次”和“拒绝” |
| 沙箱失败 | 直接失败，不降级到主机执行 |
| 模型推理 | 不展示原始思维链，展示结构化思考摘要 |
| 子 Agent 过程 | 展示思考摘要、工具调用、结果和文件变更 |
| 遥测 | 不支持，不采集、不上传 |
| Wiki / Skills | 完整管理暂定放在 P1 |

## 3. 核心工作台

采用可折叠三栏布局：

```text
┌──────────────┬──────────────────────────────┬────────────────────┐
│ 会话与导航   │ 对话与任务时间线             │ 任务检查器         │
│              │                              │                    │
│ 新建任务     │ 用户消息                     │ 路由结果           │
│ 会话列表     │ Agent 回复                   │ 计划步骤           │
│ Agent 列表   │ 工具调用卡片                 │ 子 Agent 列表      │
│ Wiki         │ 权限确认卡片                 │ 文件变更           │
│ Skills       │ 运行进度                     │ 耗时与 Token       │
└──────────────┴──────────────────────────────┴────────────────────┘
```

### 3.1 中间区域：任务时间线

默认按真实阅读顺序显示用户真正关心的内容：

```text
用户：分析项目结构并给出建议
  ↓
当前任务：分析项目结构
Agent：依赖分析，正在检查锁文件
工具调用：读取 pyproject.toml
工具调用：读取 uv.lock
计划已动态调整 1 次
文件变更：修改 2 个文件
  ↓
Agent 最终回答（Markdown）
```

Agent 的计划是动态运行状态，不是固定项目计划。客户端只展示当前计划的第一条任务，不完整铺开所有步骤，也不尝试根据旧步骤推断后续执行。`plan.updated` 到达后直接替换当前任务，并提示调整次数。

工具、文件变化和 Agent 动作位于最终回答之前。技术日志、完整工具输出和大段内容默认折叠，用户可以按需展开。最终回答使用 GitHub Flavored Markdown 展示标题、列表、表格、引用、链接和代码块。

### 3.2 已确认的视觉方向

- 白色浅色主题；
- 专业开发者工具风格；
- 页面背景、侧栏、时间线和检查器使用浅色层级区分；
- 蓝色表示当前选择和运行状态；
- 绿色表示成功；
- 橙色表示警告和工具授权；
- 不使用大面积黑色背景；
- 不使用花哨渐变和装饰性动画；
- 优先保证信息清晰、状态可辨识和长时间使用的舒适度。

### 3.3 右侧区域：任务检查器

右侧检查器展示当前任务的结构化状态：

- Direct 或 Plan；
- 任务目标；
- 当前计划的第一条任务；
- 当前任务依赖；
- 计划修订次数；
- 主 Agent 和子 Agent；
- 工具调用；
- 文件变更；
- 运行状态；
- 模型、Token 和耗时；
- 错误和重试入口。

选择某个步骤或子 Agent 后，检查器切换到对应详情。

## 4. 子 Agent 可视化

子 Agent 不能只显示“运行中”。用户需要看见它正在做什么。

### 4.1 子 Agent 列表

每个子 Agent 显示：

- 名称；
- 任务；
- 等待、运行、完成、失败或取消状态；
- 当前动作；
- 已运行时间；
- 工具调用数量；
- 文件变更数量。

### 4.2 子 Agent 详情

点击子 Agent 后展示：

```text
子 Agent：依赖分析
状态：运行中
任务：检查项目依赖与锁文件一致性

思考摘要：
发现 pyproject.toml 与 uv.lock 可能不一致，
下一步检查锁文件中的项目版本和依赖列表。

执行时间线：
14:32:01 读取 pyproject.toml
14:32:03 读取 uv.lock
14:32:05 搜索 litellm 依赖
14:32:07 运行 uv lock --check
14:32:16 命令失败：锁文件需要更新

文件变更：暂无
当前动作：正在整理检查结果
```

### 4.3 思考信息边界

展示：

- 为什么执行当前步骤；
- 当前发现；
- 为什么选择下一个工具；
- 遇到的阻塞；
- 下一步动作；
- Replanner 调整计划的原因。

不展示：

- 模型原始思维链；
- 不稳定的内部草稿；
- Provider 私有推理字段；
- 可能包含敏感上下文的原始请求。

产品展示的是可理解、可记录的结构化思考摘要，以及完整可验证的执行动作。

## 5. MVP 功能

### 5.1 对话与会话

- 新建、切换、重命名和删除会话；
- 恢复历史会话；
- Markdown 和代码块；
- 发送、停止、重新发送；
- 流式显示 Agent 回复。

### 5.2 任务运行

- 展示 Direct 或 Plan 路由；
- 只展示动态计划的第一条当前任务和依赖；
- 展示 Replanner 调整次数，不铺开历史计划；
- 展示主 Agent 和子 Agent 状态；
- 展示子 Agent 思考摘要；
- 展示所有 Agent 的工具调用；
- 展示文件变更；
- 支持取消任务；
- 支持失败后重新发起。

### 5.3 工具权限

危险工具执行前展示：

- 工具名称；
- 执行目的；
- 参数；
- 工作目录；
- 影响文件；
- 是否在沙箱内；
- 风险提示。

用户只能选择：

- 允许一次；
- 拒绝。

拒绝后保留事件记录。沙箱失败时工具直接失败，不允许切换到主机执行。

### 5.4 设置

- 模型渠道；
- 模型名称；
- API 地址；
- API Key；
- 连接测试；
- 默认工作区；
- 沙箱状态；
- 日志级别。

API Key 只交给本地后端保存，前端只显示掩码。

### 5.5 状态恢复

- 页面刷新后会话不丢失；
- 页面刷新不终止正在运行的任务；
- 重新连接后恢复任务快照；
- 后端异常退出后，客户端不能永久停留在“运行中”。

## 6. P1 功能

- Wiki 页面查看、搜索、编辑和删除；
- 展示当前任务使用了哪些 Wiki 记忆；
- Skills 列表、详情、刷新和启停；
- Agent 身份和权限管理；
- Heartbeat 管理；
- 文件 Diff；
- Plan DAG 图；
- Replanner 前后计划对比；
- 日志与诊断包；
- 更详细的 Token 和耗时统计。

## 7. 客户端 MVVM 约束

客户端必须保持 UI 与逻辑分离：

```text
View
  只负责渲染和转发用户操作

ViewModel
  管理页面状态、任务状态、加载、错误、取消和重试

Model
  Conversation、Run、Plan、Step、Agent、ToolCall、FileChange

Service / Repository
  HTTP、WebSocket、缓存、DTO 转换和本地持久化
```

硬性约束：

- View 不直接请求 API；
- View 不解析日志判断任务状态；
- 客户端不自行推演 Agent 状态；
- 服务端状态是事实来源；
- 网络 DTO 与页面 Model 分离；
- 每个 Run、Step、Agent、ToolCall 都有稳定 ID。

建议核心 ViewModel：

- `ConversationViewModel`；
- `RunViewModel`；
- `PlanViewModel`；
- `AgentViewModel`；
- `ToolApprovalViewModel`；
- `SettingsViewModel`。

## 8. 后端必须提供的能力

详细字段、接口、事件和恢复流程见[《前后端通信协议》](technical/前后端通信协议.md)。

正式客户端不能靠解析 CLI 输出工作。后端需要提供：

- 统一任务入口；
- 任务快照；
- WebSocket 实时事件；
- 流式回复；
- 工具授权等待与恢复；
- 任务取消；
- 会话查询；
- 配置查询与保存；
- 稳定的错误类型。

关键事件包括：

```text
run.started
route.decided
plan.created
plan.updated
step.started
step.completed
agent.started
agent.progress
agent.completed
assistant.delta
tool.approval_required
tool.started
tool.completed
file.changed
run.completed
run.failed
run.cancelled
```

所有子 Agent 事件必须携带 `agent_id` 和 `parent_agent_id`，保证工具调用、思考摘要和文件变更可以归属到正确的 Agent。

## 9. 安全规则

- 本地服务只监听回环地址；
- 不上传会话、日志、配置和使用数据；
- 不实现遥测；
- GUI 默认不自动批准危险工具；
- 沙箱失败不允许降级到主机；
- 删除文件、执行 Shell、写入敏感位置必须明确提示；
- 工具授权和执行结果必须保留记录；
- 客户端不得记录完整 API Key。

## 10. 开发顺序

### 阶段 0：清理基线

- 删除 OpenWebUI 接入；
- 收口重复的 API 服务入口；
- 补齐并跑通 React 原型；
- 修复依赖锁和测试基线。

### 阶段 1：运行协议

- 定义 Run、Plan、Step、Agent、ToolCall 模型；
- 定义命令、快照和事件；
- 后端支持流式输出、授权和取消；
- CLI 与 Web 使用同一业务入口。

### 阶段 2：工作台 MVP

- 按 MVVM 重构 React 客户端；
- 完成会话和对话；
- 完成计划、步骤和子 Agent；
- 完成工具授权和文件变更；
- 完成刷新恢复和错误处理。

### 阶段 3：P1 能力

- Wiki、Skills、Agent 和 Heartbeat；
- 文件 Diff；
- Plan DAG；
- 诊断与统计。

### 阶段 4：桌面封装

- 封装 macOS 桌面应用；
- 管理 Python 服务生命周期；
- 安全存储 API Key；
- 应用签名和更新。

## 11. MVP 验收标准

1. 用户可以配置模型并成功发起任务；
2. Direct 和 Plan 任务都能正确展示；
3. 用户可以看到每个子 Agent 的任务、状态和当前动作；
4. 用户可以看到子 Agent 的结构化思考摘要；
5. 用户可以看到子 Agent 的工具参数、结果和文件变更；
6. 工具授权能够阻塞任务，并在允许或拒绝后正确继续；
7. 沙箱失败时不会执行主机降级；
8. 用户可以取消运行，取消后不再发起新工具调用；
9. 页面刷新后会话和运行状态可以恢复；
10. GUI 不自动批准危险操作；
11. 客户端符合 MVVM，View 不直接调用 API；
12. CLI 原有核心能力保持可用；
13. 客户端构建、后端测试和关键端到端流程在 CI 中通过。

`UI规范.md` 至少记录：

- 组件清单；

给编码 Agent 下达任务时，明确要求它先阅读：

1. `docs/可视化客户端产品文档.md`；
2. `docs/design/UI规范.md`；
3. `docs/design/` 中对应页面截图；
4. CodeGraph 中现有客户端和服务端结构。

推荐任务描述：

```text
请按照 docs/design/ 中的 UI 规范和截图实现 QRClaw 工作台。
开始前先阅读产品文档和 UI规范.md，并使用 CodeGraph 分析现有代码。
客户端必须采用 MVVM，View 只负责渲染和转发操作，
API、WebSocket、运行状态和错误处理必须放在 ViewModel、Service 或 Repository。
实现后对照截图逐项检查布局、状态、颜色和交互，不得自行改变已确认的产品结构。
```

截图负责说明“应该长什么样”，UI 规范负责说明“应该怎么工作”，产品文档负责说明“为什么做和做哪些功能”。编码 Agent 必须同时使用三者，不能只看截图猜交互。
