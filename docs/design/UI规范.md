## 2. 页面结构

工作台使用三栏布局：

| 区域 | 基准宽度 | 职责 |
|---|---:|---|
| 顶栏 | 高 46 px | 产品、工作区、连接状态、设置 |
| 左栏 | 190 px | 新建任务、会话、Agent、Wiki、Skills 导航 |
| 中栏 | 自适应 | 对话、计划步骤、Agent 执行时间线、输入框 |
| 右栏 | 280 px | 当前任务、计划、Agent、工具、变更详情 |

布局规则：

- 中栏最小宽度 680 px；
- 窗口变窄时优先折叠右栏，再折叠左栏；
- 顶栏固定，左右栏独立滚动，中栏时间线独立滚动；
- 输入框固定在中栏底部；
- 工具授权使用居中模态框，打开时禁止操作背景内容。

## 3. 视觉令牌

| 用途 | 颜色 |
|---|---|
| 页面与卡片背景 | `#FFFFFF` |
| 侧栏与检查器背景 | `#F7F9FC` |
| 弱背景/代码块 | `#F1F5F9` |
| 边框 | `#D5DDE7` |
| 主文字 | `#1F2937` |
| 次文字 | `#68778A` |
| 主色/运行中 | `#3376BA` |
| 成功 | `#27865B` |
| 警告/待授权 | `#C57A16` |
| 错误 | `#C2413A` |

统一规则：

- 正文 13～14 px，辅助文字 11～12 px，标题 14～16 px；
- 卡片圆角 8 px，按钮圆角 6 px，模态框圆角 12 px；
- 使用细边框和轻阴影，不使用大面积黑色、渐变或装饰动画；
- 状态不能只依赖颜色，必须同时显示文字或图标。

## 4. 三种核心状态

### 4.1 计划执行

- 中栏按时间顺序展示用户任务、当前任务、Agent、工具调用和最终回答；
- 动态计划只展示 `steps[0]`，不铺开完整步骤列表；
- `plan.updated` 只更新当前任务，并轻量提示计划调整次数；
- 当前任务使用蓝色强调，完成使用绿色，失败使用红色；
- 右栏展示目标、当前第一条任务、计划修订次数、资源统计和当前状态；
- Agent 最终回答必须位于工具执行过程之后，并使用 Markdown 渲染；
- 技术日志与长工具结果默认折叠。

### 4.2 子 Agent 详情

- 顶部显示 Agent 名称、状态和运行时间；
- 时间线展示结构化思考摘要、工具调用、结果、失败和文件变更；
- 右栏展示父 Agent、任务、当前判断、调用统计和最近动作；
- 允许查看工具参数与结果，不展示模型原始思维链。

### 4.3 工具授权

- 任务进入等待状态，背景降低对比度；
- 模态框必须显示 Agent、工具、目的、工作目录、执行环境、参数和风险；
- 只提供“拒绝”和“允许一次”；
- 不提供“始终允许”；
- 沙箱失败直接失败，禁止降级到主机执行。

## 5. 状态与交互

| 状态 | 页面反馈 |
|---|---|
| 加载 | 保留页面骨架，局部区域显示加载状态 |
| 空白 | 说明当前没有内容，并提供唯一主要操作 |
| 断线 | 顶栏显示断线；自动重连并按协议恢复快照 |
| 失败 | 时间线保留失败事件；展示可理解原因和重试入口 |
| 已取消 | 停止追加运行事件，明确显示取消时间 |
| 待授权 | 暂停对应工具调用，展示授权模态框 |

用户点击步骤、Agent、工具或文件变更时，右栏切换到对应详情；关闭右栏后，中栏占用释放空间。

## 6. MVVM 硬性约束

- `View` 只渲染状态并转发操作，不直接调用 HTTP 或 WebSocket；
- `ViewModel` 管理页面状态、选择、授权、取消、重试和错误；
- `Service / Repository` 负责通信、重连、缓存和 DTO 转换；
- 页面不得解析中文日志推导状态；
- 服务端快照和事件是运行状态的唯一事实来源；
- 网络 DTO 与页面 Model 分离；
- Run、Step、Agent、ToolCall 组件只接收明确的展示模型和回调。

## 8. 前端验收

- 1440 × 900 下与三张基准图的结构、间距和状态层级一致；
- 1280 px 宽度下不出现横向页面滚动；
- 三种核心状态可以使用模拟数据独立演示；
- 所有按钮具有悬停、聚焦、禁用和执行中状态；
- 键盘可以完成焦点移动、打开详情、授权和拒绝；
- View 中不存在直接网络请求和日志解析；
- 工具授权只能允许一次或拒绝；
- 沙箱失败提示中不出现主机降级入口。

## 9. 给编码 Agent 的读取顺序

1. 阅读本规范和三张基准图；
2. 阅读产品文档的第 2～5、7～9、11 节；
3. 阅读前后端通信协议；
4. 使用 CodeGraph 查看现有前端入口、组件依赖和后端 API；
5. 先用模拟数据完成 MVVM 页面骨架，再接入真实协议。
