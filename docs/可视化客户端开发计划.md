# QRClaw 可视化客户端开发计划

> 基线：`develop`  
> 目标：macOS 本地 Web 多 Agent 工作台 MVP  
> 原则：先固定设计和协议，再开发后端，最后接入 UI

## 1. 总体顺序

```text
设计交付
  → 清理工程基线
  → 定义运行协议
  → 改造 Agent 后端
  → 搭建 MVVM 客户端
  → 接入工作台功能
  → 联调与验收
```

第一件事不是写页面，而是把已经确认的 UI 固化为截图和 UI 规范。没有设计交付物时，编码 Agent 容易自行改变布局和交互。

## 2. 里程碑计划表

| 顺序 | 阶段 | 主要工作 | 完成标志 | 单人预估 |
|---:|---|---|---|---:|
| 1 | 设计交付 | 导出三张 UI 图，编写 UI 规范 | 编码 Agent 不依赖当前对话也能理解设计 | 1～2 天 |
| 2 | 工程基线 | 删除 OpenWebUI，统一 API 入口，修复前端构建、锁文件和测试 | 前后端能独立启动，基础测试通过 | 2～4 天 |
| 3 | 运行协议 | 定义 Run、Plan、Step、Agent、ToolCall、事件和状态机 | 协议文档和数据模型评审通过 | 2～4 天 |
| 4 | 后端改造 | 事件流、流式输出、工具授权、取消、快照恢复 | 不依赖 CLI 日志也能完整观察任务 | 7～10 天 |
| 5 | MVVM 客户端 | 重构目录，搭建 ViewModel、Servce、Repository 和页面框架 | View 不直接访问 API | 4～6 天 |
| 6 | MVP 接入 | 会话、计划、子 Agent、工具授权、文件变更和恢复 | 三种确认 UI 状态使用真实数据运行 | 8～12 天 |
| 7 | 质量验收 | 单元、集成、端到端、安全和异常恢复测试 | MVP 验收项全部通过 | 4～6 天 |

单人完整开发约 28～44 个工作日。使用多个 Agent 可以缩短编码时间，但协议设计、联调和验收仍需要串行确认。

## 3. 分阶段任务

### 阶段 1：设计交付

- [x] 导出“计划执行”浅色 UI 图；
- [x] 导出“子 Agent 详情”浅色 UI 图；
- [x] 导出“工具授权”浅色 UI 图；
- [x] 创建 `docs/design/UI规范.md`；
- [x] 记录布局、颜色、组件、状态和交互；
- [x] 把产品文档、UI 规范和截图互相链接。

设计交付已完成，可以开始正式客户端开发。

### 阶段 2：工程基线

- [ ] 删除 OpenWebUI 专用脚本、接入和说明；
- [ ] 收口 `api_server.py` 与 `qrclaw/server/app.py`；
- [ ] 确定唯一的本地服务启动命令；
- [ ] 补齐 React 原型缺少的 API 和类型层；
- [ ] 确保 `npm run build` 通过；
- [ ] 更新并校验 `uv.lock`；
- [ ] 修复现有测试收集错误和失败测试；
- [ ] 建立前后端基础 CI。

完成标准：新开发者克隆项目后，可以按文档启动服务、构建前端并运行测试。

### 阶段 3：运行协议

协议基线见[《前后端通信协议》](technical/前后端通信协议.md)，实现前需要完成待确认事项评审。

- [ ] 定义 `Conversation` 和 `Message`；
- [ ] 定义 `Run` 和运行状态机；
- [ ] 定义 `Plan`、`Step` 和依赖关系；
- [ ] 定义 `Agent`、`agent_id` 和 `parent_agent_id`；
- [ ] 定义 `ToolCall`、授权和结果；
- [ ] 定义 `FileChange`；
- [ ] 定义 WebSocket 事件信封、顺序号和重连规则；
- [ ] 定义 HTTP 命令、查询和错误格式；
- [ ] 编写协议示例和契约测试。

完成标准：前端和后端可以只根据协议文档并行开发，不需要互相猜字段。

### 阶段 4：后端改造

- [ ] 使用事件发布器替代核心流程中的直接界面输出；
- [ ] 使用授权提供器替代 `input()` 和 GUI 自动确认；
- [ ] 主 Agent 与子 Agent 的事件都带正确 ID；
- [ ] 工具调用归属到正确 Agent；
- [ ] 产生结构化思考摘要事件；
- [ ] 支持流式 Agent 输出；
- [ ] 支持取消模型调用和工具执行；
- [ ] 支持运行快照；
- [ ] 支持 WebSocket 断线补发；
- [ ] 沙箱失败直接失败，不允许主机降级；
- [ ] CLI 改为复用同一运行服务。

完成标准：使用测试客户端可以看到完整任务过程，并完成允许、拒绝、取消和恢复。

### 阶段 5：MVVM 客户端骨架

- [ ] 建立 `models/`；
- [ ] 建立 `services/` 和 WebSocket 客户端；
- [ ] 建立 `repositories/`；
- [ ] 建立 `viewmodels/`；
- [ ] 建立纯展示 `views/` 和组件；
- [ ] 完成白色主题和三栏工作台；
- [ ] 完成路由、加载、空白、错误和断线状态；
- [ ] 建立 ViewModel 单元测试。

完成标准：页面使用模拟数据可以完整切换三种确认状态，View 中没有直接 API 调用。

### 阶段 6：MVP 功能接入

- [ ] 会话列表、创建、切换、重命名和删除；
- [ ] 消息发送、Markdown 和流式回复；
- [ ] Direct 与 Plan 路由展示；
- [ ] 计划步骤和当前步骤；
- [ ] 子 Agent 列表和状态；
- [ ] 子 Agent 思考摘要；
- [ ] 子 Agent 工具参数和结果；
- [ ] 文件变更列表；
- [ ] 允许一次和拒绝；
- [ ] 任务取消；
- [ ] 页面刷新和断线恢复；
- [ ] 模型与本地服务设置。

完成标准：产品文档中的三种 UI 状态全部由真实后端事件驱动。

### 阶段 7：质量验收

- [ ] Direct 任务端到端测试；
- [ ] Plan 与并行子 Agent 端到端测试；
- [ ] 工具允许和拒绝测试；
- [ ] 任务取消测试；
- [ ] WebSocket 断线恢复测试；
- [ ] 服务异常退出恢复测试；
- [ ] 沙箱失败不降级测试；

完成标准：产品文档第 11 节的 MVP 验收标准全部通过。

## 4. 前两周建议安排

| 时间 | 工作 |
|---|---|
| 第 1～2 天 | 完成截图和 `UI规范.md` |
| 第 3～5 天 | 删除 OpenWebUI、统一服务入口、修复前端构建 |
| 第 6～7 天 | 修复依赖锁和测试基线 |
| 第 8～10 天 | 定义运行模型、事件和状态机 |

两周结束时暂时不追求完整页面，应该得到一个设计明确、构建稳定、协议清楚的开发基线。

## 5. 开发期间不要提前做

- 不要先开发 Wiki、Skills 和 Heartbeat 管理；
- 不要先画复杂 Plan DAG；
- 不要先封装 macOS 桌面应用；
- 不要同时保留多套正式 API；
- 不要让前端解析中文日志；
- 不要把 API 和 WebSocket 逻辑写进 View；
- 不要在沙箱失败后自动执行主机命令；
- 不要为了赶进度跳过协议和自动化测试。

## 6. 当前立即执行的三件事

1. 对照 `docs/design/` 完成一次设计确认；
2. 进入“工程基线清理”；
3. 基线稳定后完成运行协议评审，并开始 MVVM 客户端骨架。
