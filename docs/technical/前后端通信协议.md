# QRClaw 前后端通信协议

> 协议版本：0.1 讨论稿  
> 适用范围：macOS 本地 Web MVP  
> 后端：Python + FastAPI  
> 前端：React + MVVM

## 1. 目的

本文档约定 QRClaw 工作台前端与本地后端之间的通信方式。

核心目标：

- 前端能够实时展示主 Agent 和子 Agent；
- 每个工具调用都能归属到正确 Agent；
- 危险工具可以等待用户允许或拒绝；
- 用户可以取消任务；
- 页面刷新或 WebSocket 断线后可以恢复状态；
- 前端不解析 CLI 输出或中文日志；
- CLI 与 Web 最终复用同一套 Agent 运行服务。

## 2. 通信方式

采用两种通信通道：

| 通道 | 用途 |
|---|---|
| HTTP | 创建任务、查询快照、会话管理、授权、取消和设置 |
| WebSocket | 流式文字、计划、步骤、Agent、工具和文件变更事件 |

约定地址：

```text
HTTP       http://127.0.0.1:8765/api/v1
WebSocket  ws://127.0.0.1:8765/api/v1/events
```

正式端口可以通过启动配置修改。前端不得在多个组件中硬编码地址。

## 3. 通用约定

### 3.1 数据格式

- 请求和响应使用 JSON；
- 字段名使用 `snake_case`；
- 时间使用带时区的 ISO 8601；
- ID 使用不透明字符串，前端不能解析其业务含义；
- 所有接口位于 `/api/v1`；
- 所有事件携带协议版本；
- 中文日志不属于通信协议。

### 3.2 核心 ID

```text
conversation_id  会话
message_id       消息
run_id           一次任务运行
plan_id          一份计划
step_id          计划步骤
agent_id         Agent 实例
parent_agent_id  父 Agent
tool_call_id     工具调用
approval_id      授权请求
event_id         事件
```

同一名称的子 Agent 多次运行时，必须生成不同的 `agent_id`。

### 3.3 HTTP 成功响应

```json
{
  "data": {},
  "request_id": "req_01"
}
```

### 3.4 HTTP 错误响应

```json
{
  "error": {
    "code": "run_not_found",
    "message": "找不到指定任务",
    "retryable": false,
    "details": {}
  },
  "request_id": "req_01"
}
```

前端根据 `code` 决定处理方式，不能根据中文 `message` 判断错误类型。

## 4. 核心模型

### 4.1 Run

```json
{
  "run_id": "run_01",
  "conversation_id": "conv_01",
  "status": "running",
  "route": "plan",
  "goal": "检查项目依赖",
  "created_at": "2026-08-18T15:30:00+08:00",
  "updated_at": "2026-08-18T15:31:00+08:00",
  "last_seq": 42
}
```

Run 状态：

```text
queued
routing
running
waiting_approval
cancelling
completed
failed
cancelled
```

当部分子 Agent 等待授权、其他子 Agent 仍可运行时，Run 保持 `running`。只有全部可执行路径都被授权阻塞时，Run 才进入 `waiting_approval`。

### 4.2 Agent

```json
{
  "agent_id": "agent_dependency",
  "parent_agent_id": "agent_main",
  "run_id": "run_01",
  "step_id": "step_01",
  "name": "依赖分析",
  "task": "检查项目依赖和锁文件",
  "status": "running",
  "current_action": "正在读取 uv.lock",
  "decision_summary": "先核对锁文件，再判断是否需要重新生成"
}
```

Agent 状态：

```text
pending
running
waiting_approval
completed
failed
cancelled
```

`decision_summary` 是结构化思考摘要，不是模型原始思维链。

### 4.3 ToolCall

```json
{
  "tool_call_id": "tool_01",
  "run_id": "run_01",
  "agent_id": "agent_dependency",
  "name": "read_file",
  "arguments": {
    "path": "/project/pyproject.toml"
  },
  "status": "running",
  "started_at": "2026-08-18T15:31:00+08:00"
}
```

ToolCall 状态：

```text
pending
waiting_approval
running
completed
failed
denied
cancelled
```

## 5. HTTP API

### 5.1 系统

```text
GET /health
GET /capabilities
```

`/capabilities` 返回后端支持的协议版本、功能和限制，前端据此决定是否显示相关入口。

### 5.2 会话

```text
GET    /conversations
POST   /conversations
GET    /conversations/{conversation_id}
PATCH  /conversations/{conversation_id}
DELETE /conversations/{conversation_id}
GET    /conversations/{conversation_id}/messages
```

创建会话：

```json
{
  "title": "项目依赖检查",
  "workspace_path": "/Users/example/project"
}
```

删除会话需要前端二次确认。后端不得根据前端传入的任意路径删除工作区文件。

### 5.3 创建任务

```text
POST /runs
```

请求：

```json
{
  "conversation_id": "conv_01",
  "content": "检查项目依赖并给出修复方案",
  "client_request_id": "client_01"
}
```

响应状态使用 `202 Accepted`：

```json
{
  "data": {
    "run_id": "run_01",
    "status": "queued"
  },
  "request_id": "req_01"
}
```

`client_request_id` 用于避免用户重复点击产生两个相同任务。

### 5.4 查询任务快照

```text
GET /runs/{run_id}
```

返回内容至少包含：

- Run；
- 当前计划和步骤；
- 主 Agent 与子 Agent；
- 未结束工具调用；
- 待处理授权；
- 最后一条事件序号。

快照用于首次进入页面和断线恢复，不代替实时事件。

### 5.5 取消任务

```text
POST /runs/{run_id}/cancel
```

请求：

```json
{
  "reason": "user_requested"
}
```

接口只表示后端收到取消请求。前端必须等待 `run.cancelled` 或 `run.failed`，不能自行将任务标记为已取消。

### 5.6 处理工具授权

```text
POST /tool-approvals/{approval_id}/resolve
```

允许一次：

```json
{
  "decision": "allow_once"
}
```

拒绝：

```json
{
  "decision": "deny"
}
```

同一 `approval_id` 只能成功处理一次。重复请求返回原处理结果，不重复执行工具。

### 5.7 设置

```text
GET  /settings
PUT  /settings
POST /settings/test-connection
```

读取设置时不得返回完整 API Key，只返回：

```json
{
  "provider": "litellm",
  "model": "provider/model",
  "base_url": "http://127.0.0.1:4000",
  "has_api_key": true,
  "api_key_masked": "sk-••••••••1234"
}
```

## 6. WebSocket 协议

### 6.1 连接

```text
GET ws://127.0.0.1:8765/api/v1/events
```

连接成功后，服务端发送：

```json
{
  "type": "connection.ready",
  "version": "1",
  "connection_id": "conn_01"
}
```

客户端订阅任务并提交已收到的最后序号：

```json
{
  "type": "subscribe",
  "runs": [
    {"run_id": "run_01", "after_seq": 42}
  ]
}
```

服务端补发 `seq > 42` 的事件，然后继续实时推送。

### 6.2 事件信封

```json
{
  "version": "1",
  "event_id": "evt_43",
  "seq": 43,
  "timestamp": "2026-08-18T15:31:10+08:00",
  "conversation_id": "conv_01",
  "run_id": "run_01",
  "agent_id": "agent_dependency",
  "parent_agent_id": "agent_main",
  "type": "tool.started",
  "data": {}
}
```

`seq` 在单个 Run 内单调递增。前端使用 `event_id` 去重，使用 `seq` 检查缺失事件。

### 6.3 MVP 事件

| 事件 | 用途 |
|---|---|
| `run.started` | 任务开始 |
| `run.status_changed` | Run 状态变化 |
| `route.decided` | Direct 或 Plan |
| `plan.created` | 创建计划 |
| `plan.updated` | Replanner 调整计划 |
| `step.started` | 步骤开始 |
| `step.completed` | 步骤完成 |
| `step.failed` | 步骤失败 |
| `agent.started` | Agent 开始 |
| `agent.progress` | 当前动作或结构化思考摘要变化 |
| `agent.completed` | Agent 完成 |
| `agent.failed` | Agent 失败 |
| `assistant.delta` | 流式文字片段 |
| `assistant.completed` | 完整回复结束 |
| `tool.approval_required` | 等待用户授权 |
| `tool.started` | 工具开始 |
| `tool.completed` | 工具完成 |
| `tool.failed` | 工具失败 |
| `file.changed` | 文件变化 |
| `usage.updated` | Token 和耗时变化 |
| `run.completed` | 任务完成 |
| `run.failed` | 任务失败 |
| `run.cancelled` | 任务取消完成 |

### 6.4 子 Agent 进度事件

```json
{
  "version": "1",
  "event_id": "evt_20",
  "seq": 20,
  "timestamp": "2026-08-18T15:31:00+08:00",
  "conversation_id": "conv_01",
  "run_id": "run_01",
  "agent_id": "agent_dependency",
  "parent_agent_id": "agent_main",
  "type": "agent.progress",
  "data": {
    "current_action": "正在核对 uv.lock",
    "decision_summary": "项目依赖声明已经变化，先检查锁文件差异，不直接修改文件"
  }
}
```

### 6.5 工具授权事件

```json
{
  "version": "1",
  "event_id": "evt_21",
  "seq": 21,
  "timestamp": "2026-08-18T15:31:05+08:00",
  "conversation_id": "conv_01",
  "run_id": "run_01",
  "agent_id": "agent_dependency",
  "parent_agent_id": "agent_main",
  "type": "tool.approval_required",
  "data": {
    "approval_id": "approval_01",
    "tool_call_id": "tool_02",
    "tool_name": "run_shell",
    "purpose": "检查锁文件一致性",
    "arguments": {"command": "uv lock --check"},
    "cwd": "/Users/example/project",
    "sandbox": {
      "enabled": true,
      "network": "none"
    },
    "risk_level": "medium"
  }
}
```

## 7. 关键通信流程

### 7.1 正常任务

```text
前端 POST /runs
  → 后端返回 run_id
  → WebSocket 推送 run.started
  → route.decided
  → plan.created（Plan 模式）
  → step / agent / tool 事件
  → assistant.delta
  → assistant.completed
  → run.completed
```

### 7.2 工具授权

```text
后端 tool.approval_required
  → 对应 Agent 进入 waiting_approval
  → 前端显示授权卡片
  → 用户 POST /tool-approvals/{id}/resolve
  → 允许：tool.started → tool.completed
  → 拒绝：ToolCall 进入 denied，Agent 获得拒绝结果
```

后端等待授权期间不得占用 HTTP 请求线程。授权必须通过可等待对象、队列或任务协调器恢复。

### 7.3 页面刷新与断线恢复

```text
前端重新打开
  → GET /runs/{run_id} 获取快照
  → 连接 WebSocket
  → subscribe(run_id, after_seq)
  → 后端补发缺失事件
  → 继续接收实时事件
```

快照与事件都必须支持幂等归并，重复事件不能产生重复消息或工具卡片。

### 7.4 取消

```text
前端 POST /runs/{run_id}/cancel
  → 后端推送 run.status_changed(cancelling)
  → 停止后续模型和工具调用
  → 终止可终止的外部进程
  → 推送 run.cancelled
```

取消完成前，前端显示“正在取消”，不能立即显示“已取消”。

## 8. 前后端职责

### 8.1 后端负责

- 生成和维护所有业务 ID；
- 维护 Run、Plan、Step、Agent 和 ToolCall 状态；
- 发布结构化事件；
- 保存会话和运行快照；
- 等待并处理授权；
- 执行取消；
- 控制沙箱和文件权限；
- 保存 API Key；
- 记录中文日志。

### 8.2 前端负责

- 通过 ViewModel 发出用户命令；
- 展示后端快照和事件；
- 按 `event_id` 去重；
- 发现事件序号缺失时重新同步；
- 保存界面偏好；
- 展示允许一次和拒绝；
- 展示连接、加载和错误状态。

前端不得：

- 解析日志推断 Agent 状态；
- 自行将任务标记为完成或取消；
- 保存完整 API Key；
- 绕过工具授权；
- 在沙箱失败后请求主机降级；
- 在 View 组件中直接调用 HTTP 或 WebSocket。

## 9. MVVM 对接

```text
View
  → ViewModel
  → Repository
  → HTTPService / WebSocketService

WebSocketService
  → EventRepository
  → RunViewModel / PlanViewModel / AgentViewModel
  → View
```

建议映射：

| 协议内容 | 客户端负责对象 |
|---|---|
| 会话和消息 | `ConversationViewModel` |
| Run 状态 | `RunViewModel` |
| 计划与步骤 | `PlanViewModel` |
| 主 Agent 和子 Agent | `AgentViewModel` |
| 工具授权 | `ToolApprovalViewModel` |
| HTTP | `ApiService` |
| WebSocket | `EventService` |
| 快照与事件归并 | Repository 层 |

## 10. 安全要求

- 默认只监听 `127.0.0.1`；
- 前端与后端使用启动时生成的本地访问令牌；
- CORS 只允许实际客户端来源；
- 不上传会话、事件、日志和配置；
- 不支持遥测；
- API Key 不通过查询接口返回；
- GUI 不使用 `auto_confirm=True`；
- 沙箱失败时工具直接失败；
- 授权结果与工具执行结果必须记录；
- 文件路径在后端进行规范化和权限校验。

## 11. 协议演进规则

- 当前版本为 `0.1`，只覆盖 MVP；
- 新增可选字段保持向后兼容；
- 删除或重命名字段必须升级协议版本；
- 事件类型不能复用为不同语义；
- 协议变更必须同时更新文档、后端模型、前端类型和契约测试；
- 实现过程中允许完善细节，但不能未经评审改变核心状态和事件语义。

## 12. 实施前待确认

1. 运行事件只保存在内存，还是写入本地事件文件；
2. 补发事件的保留时间和数量上限；
3. 是否允许一个会话同时运行多个 Run；
4. Shell 外部进程的取消方式；
5. `file.changed` 由工具主动上报，还是增加工作区文件监控；
6. 通用 OpenAI 兼容接口是否作为独立开发者能力保留。

这些事项在后端实施前确认，不影响当前产品和 UI 设计。
