# 六张方向卡

秒数轮盘：S=08 → 网页 09「像素游戏横版叙事」，东亚 09「田中一光几何平面构成」。
外观账本为空，没有需要避开的近期样子。

## A · 最佳设计师 · iA（Oliver Reichenstein）：「工作文档」

- **逻辑与来源：** iA 的主张是「网页设计 95% 是排印」，iA Writer 的 Focus Mode 会把当前段落之外的文字调淡（参考板第 3 张）。
- **借的是什么：** 单一阅读列，约 34 个汉字宽；正文用中文衬线 17px、行高 1.9；元信息全部用等宽小字；当前这一轮正常显示，更早的轮次调到 45% 灰；没有卡片、没有阴影，层级只靠字号和灰度。
- **主角素材：** 文字本身，也就是长回复；Agent 的工作过程变成页边批注（等宽字的工具计数和时间）。
- **骨架：** 左侧窄会话索引，中间是文档，右侧页边写批注（工具、子 Agent、写入的记忆）；输入框像文档最后一行。
- **胆量花在哪：** 更早的对话直接调淡，把注意力全给当前这一轮。
- **form 来自内容的哪里：** 这个用户的回复动辄上千字、带代码路径。它首先是一份要读的文档，其次才是聊天。

## B · 最佳设计师 · Teenage Engineering：「仪器」

- **逻辑与来源：** TE 设计 OP-1 和 TX-6 的思路是把复杂状态做成实体面板：一块小屏、编号的旋钮、按步进排列的音序器。
- **借的是什么：** 浅铝灰面板 #E3E3DF 加黑色；只有一个高饱和橙色 #FF4F00 标「正在发生」；四个工具类别各配一个按键色（Shell、读取、搜索、记忆）；数字一律等宽；面板分区用 1px 黑线和小号编号标签。
- **主角素材：** 小精灵放在一块深色「显示屏」里；一轮里的每次工具调用排成一格音序器步进。
- **骨架：** 顶部是全宽的仪器条（显示屏、音序器、上下文表盘、Plan 拨杆），下方左边是对话轨道，右边是子 Agent 轨道。
- **胆量花在哪：** 把 107 次工具调用画成音序器格子，看一眼就知道这轮 Agent 干了多少活、主要在干什么。
- **form 来自内容的哪里：** Agent 的一轮工作本来就是按时间排列的离散步骤。

## C · 现实参照 · Linear：「工作项」

- **逻辑与来源：** linear.app 的 issue 详情页（参考板第 1 张）：左侧工作区导航，中间是 Activity 流，右侧是属性栏（Status、Assignee、Cycle）。
- **借的是什么：** 深色中性底 #101012，面板之间只用 1px #232326 分隔；13px 紧凑元信息；Activity 流里系统事件压成一行灰字（「Linear created the issue · 2min ago」），只有人写的内容才放大；右栏是属性和数值；首页是「收件箱」。
- **主角素材：** 会话本身作为一个工作项：状态、规模、写入的记忆、压缩次数都是属性。
- **骨架：** 三栏：导航和会话收件箱，Activity 流，属性栏。第二屏是会话收件箱首页，按「需要你回复 / 运行中 / 已完成」分组。
- **胆量花在哪：** 会话不再是聊天记录，而是有状态、有属性的工作项。
- **form 来自内容的哪里：** 用户同时开着好几个持续数天的长任务，管理的是任务，不是消息。

## D · 现实参照 · Warp：「工厂点阵」

- **逻辑与来源：** warp.dev 首屏的「fig. 1 — the factory」点阵（参考板第 2 张），白底，等宽标题，柠檬黄按钮。
- **借的是什么：** 全等宽字体标题；用点阵表示并行单元，每个点是一个 Agent 或一次调用，亮蓝代表活跃；用 `[ fig. ]` 式的方括号做图注；只有一个柠檬黄的主按钮。
- **主角素材：** 会话的全部工具调用排成点阵（107 个点），按工具类型着色。
- **骨架：** 每轮对话是一个「块」，块头像命令行，块里是回复，块边是这轮的点阵。
- **胆量花在哪：** 点阵。
- **form 来自内容的哪里：** 和 B 一样来自「离散的工具调用」，但表达成整体分布，而不是时间顺序。

## E · 秒数轮盘 · 像素游戏横版叙事（还原 70%）

- **借的是什么：** 每一轮是一个「关卡」，换一套底色；小精灵在地平线上横向前进，工具调用是路上的方块；HUD 显示上下文（像血条）和 token。
- **主角素材：** 小精灵和程序化像素场景。
- **骨架：** 上方是横版场景条，下方是对话。
- **胆量花在哪：** 整个顶部都是游戏场景。
- **风险：** 万能隐喻，用力过头。去掉游戏外壳，信息反而更清楚。

## F · 秒数轮盘 · 田中一光几何构成（还原 90%）

- **借的是什么：** 米纸色底，红 #D9381E、黑、芥黄、钢蓝；在网格上用方、圆、四分之一圆拼出主图；右侧信息用小红标签分块。
- **主角素材：** 首页用几何块代表每个会话：圆代表正在运行，方代表已完成，四分之一圆代表子 Agent，面积对应规模。
- **骨架：** 首页是一张几何构成的会话海报，详情回到常规两栏。
- **胆量花在哪：** 首页是一张海报。
- **风险：** 日常每天打开的工具，海报式首页第三次看就腻了。

## 挑选

做成完整版的是 **A（iA 工作文档）**、**C（Linear 工作项）** 和 **B（TE 仪器）**：

- **气质不同：** A 安静、浅色、阅读优先；C 中性、深色、管理优先；B 大胆、铝灰橙、过程优先。三版骨架各不相同。
- **产品主张不同：** A 回答「回复是产品」，C 回答「会话是任务」，B 回答「过程是主角」。
- **只有一张偏用力：** B 的音序器有过头风险。检验方法是把它换成普通列表：107 次调用变成 107 行，信息反而更糊，所以保留。
- **落选原因：** D 和 B 都在表达工具调用，重复了；E 用力过头；F 不适合每天反复使用。

## 更正（2026-11-06）

`tool_status` 事件里每次调用记两条（开始、完成）。所以会话「你为什么不用 codegraph…」实际调用工具 107 次（run_shell 65、read_file 16 等），「记忆系统 vs codex」是 155 次。上面各处已改正。

## 自检结果（2026-11-06）

- `design_lint check`：三版红灯全部修完。黄灯是中点分隔的元信息和等宽小标签，这正是 A、B 方向卡要求的元信息写法，所以保留。C 的标题用了 Inter，沿用 Linear 的做法。
- `design_lint compare`：A 和 B 的色板距离是 0.034，被判为「撞了」，因为两版都是浅底加黑字。但两版骨架相关只有 0.21，B 还有深色显示屏、橙色和五色步进。看截图，两版气质差别很大，所以没换。
- 三版的「回放这一轮」都在浏览器里实际点过，没有控制台报错，结束后回复完整恢复。
