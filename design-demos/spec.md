# QRClaw Web 工作台重设计 · 设计 spec

三个方向共用这份 spec。这里只写「要说什么」，「长什么样」由方向卡决定。

## 项目是什么

QRClaw 是一个本地运行的 AI Agent，Web 工作台运行在 `127.0.0.1`。用户用中文对话交代任务，Agent 调用工具（Shell、读写文件、搜索、MCP）、拆出子 Agent、压缩上下文，并把经验写进可追溯来源的 Wiki 记忆。

## 现状诊断（来自 2026-11-06 的截图和真实数据）

- **界面是通用聊天应用的样子。** 真正的工作过程被藏起来了：在会话「你为什么不用 codegraph…」里，Agent 共调用工具 107 次，其中 run_shell 65 次，还启动了 4 个子 Agent、压缩了 2 次上下文，累计 6,089,838 tokens。主界面只看得到一来一回的文字，执行过程要点右上角按钮才出现，而且只列最后 6 条「工具开始 / 工具完成」，每次调用占两行（开始和完成各一行）。
- **记忆和对话是两个世界。** 同一会话里 write_wiki_page 被调用了 10 次，可聊天里看不到「这轮写进了哪页记忆」，只能去记忆库自己翻。PRODUCT 和官网都把「把经验留下来」当核心卖点，界面却没有把这条线连起来。
- **会话列表信息太少。** 4 个会话只显示截断的标题，没有状态、时间和规模。「新对话」只是占位，标题也是用户第一句话的原文截断。
- **上下文状态零散。** 压缩事件（84,557 → 23,143 tokens）是输入框上方一行 11px 灰字，上下文 29.8% 是一条很细的进度条。
- **小精灵占着 Logo 的位置**，但侧栏里的大号「开启新对话」按钮和底部的「本地工作空间」说明占的面积更大。

## 受众与场景

- **受众：** 用中文、天天用 AI 干活的开发者（即仓库主人自己）。
- **场景：** 桌面浏览器，1440 宽左右，一天里反复打开；单个会话可能持续好几天，经历上百次工具调用。窄屏（手机）要能访问全部功能。

## 核心信息（重要性从高到低）

1. 发起任务、继续对话的入口始终最容易找到。
2. Agent 正在做什么、做到哪一步：工具、子 Agent、压缩、计划都由真实事件驱动。
3. 长回复要读得舒服。
4. 这次对话留下了哪些经验（记忆页），记忆能回溯到它的来源对话。
5. 同时进行的多个会话：哪个在跑、哪个有未读回复、哪个在等我。

## 情感基调

可靠、清醒、有陪伴感。不是炫技的科幻控制台，也不是空洞的聊天框。

## 输出格式（三版统一）

- 单文件 HTML 原型，1440×900 桌面主屏，375 宽手机也要能用。
- 主屏：一个进行中的会话。用真实会话「你为什么不用 codegraph…」中「npx skills add … 现在的 qrclaw 没适配」这一轮，回放到「工具调用中」的状态。
- 第二屏：在同一文件内可切换到「首页 / 会话总览」或「记忆」，看每个方向怎么重新安排信息。

## 已知约束

- 保留现有全部能力：聊天、历史会话管理（改名、删除）、Plan 开关、流式回复、编辑或删除最后一条消息、工具与子任务记录、上下文用量与压缩提示、记忆搜索、编辑、来源和关联。
- 保持现有 API 和 ViewModel：设计只能用 `SessionDetail.events`、`wiki/status` 等已有字段能推出来的信息；需要新字段的地方必须标注。
- 使用已集成的 bloub 黑色小精灵（真实 SVG 取自运行中的界面），它的动画阶段对应 `AgentActivity.phase`。
- 中文界面；正文 ≥14px，标签 ≥12px，对比度 ≥4.5:1。
- 不编造数据：所有数字、标题、记忆页名都取自本机真实会话和 Wiki。

## 假设（用户没有回答提问，按最佳判断补齐）

- PRODUCT.md 写明「用户授权整体替换布局、配色、字体与视觉风格」，用户本次也说「不一定要用现在的展示方式」，所以三个方向都允许改信息结构，不只换皮。
- 官网用的是深蓝玻璃大脑风格，工作台不强制跟随；品牌连续性靠名称、小精灵和中文语气维持。
